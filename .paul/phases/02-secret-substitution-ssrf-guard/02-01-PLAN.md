<objective>
## Goal
Build a standalone `connectors.py` module that resolves `${KEY_NAME}` secret
placeholders in outbound request headers (never in URLs), redacts resolved
secret values from anything that gets logged/persisted, and blocks
SSRF-prone targets (private/loopback/link-local/metadata addresses).

## Purpose
This is the prerequisite for Business Agents to reach revenue-generating
external APIs at all (per PROJECT.md's core value), built so the model
never sees a real key value — matching the project's existing
propose-then-approve pattern for anything with a real-world effect.

## Output
- `agent_workforce/connectors.py` (new)
- Tests appended to `agent_workforce/test_server.py`
</objective>

<acceptance_criteria>

## AC-1: Placeholder secret resolution
```gherkin
Given a dict of headers containing a `${GROQ_API_KEY}`-style placeholder value,
  and that environment variable is set
When resolve_secrets is called
Then the placeholder is replaced with the real env var value,
  and the resolved secret values are returned separately for redaction
```

## AC-2: Placeholder in URL refused
```gherkin
Given a request URL string that itself contains a `${...}` placeholder
When resolve_secrets is called
Then it raises ValueError and no substitution happens
  (secrets never belong in a URL - they leak into history/proxy logs/Referer)
```

## AC-3: Redaction strips secret values from logged text
```gherkin
Given a text string containing a previously-resolved secret's real value
When redact is called with that value
Then the returned text has the value replaced with "[REDACTED]"
  and no longer contains the raw secret
```

## AC-4: SSRF guard blocks private/loopback/link-local/metadata targets
```gherkin
Given a URL whose hostname resolves to 127.0.0.1, 169.254.169.254,
  or a 10.0.0.0/8 address
When guard_ssrf is called
Then it raises ValueError blocking the request
```

## AC-5: SSRF guard allows normal public targets
```gherkin
Given a URL whose hostname resolves to a public IP address
When guard_ssrf is called
Then no exception is raised
```

<!-- audit-added -->
## AC-6: SSRF guard blocks unspecified addresses
```gherkin
Given a URL whose hostname resolves to 0.0.0.0 or ::  (unspecified)
When guard_ssrf is called
Then it raises ValueError
  (not covered by private/loopback/link-local/multicast/reserved checks,
  and a real SSRF bypass on some platforms)
```

<!-- audit-added -->
## AC-7: Empty-but-set secret env var is rejected, not silently substituted
```gherkin
Given a header placeholder whose referenced env var is set to an empty string
When resolve_secrets is called
Then it raises ValueError treating the secret as not configured
  (an empty value must never be silently substituted into an auth header -
  that produces a request that looks authenticated but isn't, with no
  audit trail of the failure)
```

<!-- audit-added -->
## AC-8: Redaction handles one secret value being a substring of another
```gherkin
Given secret_values containing one value that is a substring of another
  (e.g. "abc" and "abc123")
When redact is called
Then the longer value is redacted first, so no fragment of a raw secret
  remains in the output
```

</acceptance_criteria>

<tasks>

<task type="auto">
  <name>Task 1: Secret substitution + redaction</name>
  <files>agent_workforce/connectors.py, agent_workforce/test_server.py</files>
  <action>
    Create `agent_workforce/connectors.py` with a top-of-file comment
    explaining the security rationale (same style as the risk-gating
    comment at the top of jobs.py), then:

    - `PLACEHOLDER_RE = re.compile(r"\$\{([A-Za-z_][A-Za-z0-9_]*)\}")`
    - `resolve_secrets(headers: dict[str, str], url: str) -> tuple[dict[str, str], list[str]]`:
      - Raise `ValueError` immediately if `PLACEHOLDER_RE` matches anywhere
        in `url` - never substitute into a URL.
      - For each header value, replace every `${NAME}` with
        `os.environ[NAME]`; if the env var isn't set, raise `ValueError`
        with a clear message naming the missing var (never silently leave
        the literal placeholder in place).
        <!-- audit-added -->
        If the env var IS set but resolves to an empty string, also raise
        `ValueError` (treat "" the same as "not configured" - a silently
        substituted empty value produces a request that looks
        authenticated but isn't, with no audit trail of the failure).
      - Collect every resolved secret value into a list and return
        `(resolved_headers, secret_values)` so the caller can redact before
        persisting/logging anything.
    - `redact(text: str, secret_values: list[str]) -> str`: replace every
      occurrence of each non-empty value in `secret_values` with
      `"[REDACTED]"`.
      <!-- audit-added -->
      Sort `secret_values` longest-first before substituting: if one
      secret value is a substring of another, redacting the shorter one
      first would leave a raw fragment of the longer secret exposed in
      the "redacted" output.

    Avoid: reading secrets from a database or config file - env vars only,
    matching the existing `GROQ_API_KEY` convention and adding no new
    dependency.
  </action>
  <verify>`uv run python -m unittest agent_workforce.test_server` passes, including new AC-1/AC-2/AC-7/AC-8 assertions in a `ConnectorTest` class</verify>
  <done>AC-1, AC-2, AC-7, and AC-8 satisfied</done>
</task>

<task type="auto">
  <name>Task 2: SSRF guard + full test coverage</name>
  <files>agent_workforce/connectors.py, agent_workforce/test_server.py</files>
  <action>
    Add to `agent_workforce/connectors.py`:

    - `guard_ssrf(url: str) -> list[str]`: parse `url` with
      `urllib.parse.urlsplit`, resolve the hostname via
      `socket.getaddrinfo`, and for every resolved address raise
      `ValueError` if `ipaddress.ip_address(addr).is_private`,
      `.is_loopback`, `.is_link_local`, `.is_multicast`, `.is_reserved`,
      or <!-- audit-added --> `.is_unspecified` (0.0.0.0 / ::, not covered
      by the other five checks and a real SSRF bypass on some platforms)
      is true (covers RFC1918, 127.0.0.0/8, 169.254.0.0/16 including the
      cloud metadata IP, multicast, unspecified, and other reserved
      ranges). Let `socket.gaierror` on an unresolvable hostname propagate
      as-is - a bad hostname should fail loudly, not be treated as safe.
      <!-- audit-added -->
      Return the list of validated resolved addresses instead of `None`.
      A future caller (Phase 3) must connect using this already-validated
      address rather than re-resolving DNS at request time - re-resolving
      would reopen a TOCTOU/DNS-rebinding gap where the address that
      passed the check differs from the address actually connected to.

    Add a `ConnectorTest(unittest.TestCase)` class to `test_server.py`
    covering AC-1 through AC-8: use `unittest.mock.patch.dict` on
    `os.environ` for secret values; `127.0.0.1`, `169.254.169.254`, and
    `0.0.0.0` resolve without a DNS lookup so no network mocking is needed
    for the SSRF cases.
  </action>
  <verify>`uv run python -m unittest agent_workforce.test_server` passes in full with no regressions</verify>

<boundaries>

## DO NOT CHANGE
- `agent_workforce/jobs.py` (`RISKY_ACTIONS`, `apply_risky_actions`) - wiring
  a `"connector"` capability into the risky-action gate is Phase 3's job
- Any route in `agent_workforce/routes/*.py`

## SCOPE LIMITS
- No actual outbound HTTP call is made anywhere in this plan - no
  `requests`/`httpx` dependency, `connectors.py` only prepares/validates a
  request, it never sends one
- No new database table or UI for managing secrets - env vars only
- No new third-party dependency (`re`, `os`, `socket`, `ipaddress`,
  `urllib.parse` - all stdlib)
- <!-- audit-added --> SSRF protection against redirect chains is
  explicitly out of scope for this plan (nothing makes an HTTP request
  yet). Phase 3, which adds the actual HTTP client, MUST re-validate the
  target on every redirect hop with `guard_ssrf`, not just the initial URL.

<!-- audit-added -->
## SECRET HANDLING (enforced on any future integration)
- Any code path that logs or persists resolved output (e.g.
  `jobs.record_event`, the `jobs`/`job_events` tables, job `output` column)
  MUST call `redact()` with the secret values from `resolve_secrets()`
  before that text is written anywhere. Raw secret values must never reach
  a persisted log. This binds Phase 3's eventual wiring into
  `RISKY_ACTIONS`, not just this plan's own tests.

</boundaries>
